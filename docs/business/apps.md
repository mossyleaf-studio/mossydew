# Android and iPad apps

The Android and iPad apps are installed outside Google Play and the App Store. They show the website itself, so every screen and rule of the site applies unchanged, and add what a website cannot: a **home-screen widget** listing Today, with tasks to tick. The widget runs outside the website and has no session cookie, so it calls a narrow API with a **device token**.

```
App (WebView) ─ session cookie ─► https://mossydew.mossyleaf.studio (every page, /api/*)
App ─ POST /api/widget/token (session) ─► device token mdd_…
Widget ─ Authorization: Bearer mdd_… ─► GET /widget/today, POST /widget/tasks/{id}/complete|reopen
App, on sign-out ─ DELETE /widget/token (Bearer) ─► token deleted
```

- **AP1** The apps show `https://mossydew.mossyleaf.studio` in a WebView: people sign in with their mossyleaf account inside the app, as in a browser (A1); links to any other site open in the browser. The apps add ` MossyDewApp/<version>` to the WebView's user agent, so Settings says MossyDew is installed on this device instead of offering a browser install. — `MainActivity` (Android), `Browser` (iPad), `useInstall.js`
- **AP2** Once signed in, the app asks for a **device token** (`POST /api/widget/token`, session only, 201 `{"token": "mdd_" + 48 hex}`) and keeps it for its widget: whenever a signed-in MossyDew page loads, or the app comes back to the foreground, without one. Each call issues a new token, so a user can have one per device (a phone, a tablet); MossyDew keeps only its SHA-256. Signing in (`/login/check`) and signing out in the app delete the token of this device (`DELETE /widget/token`, which deletes only the token sent with it, and only for its owner), so the widget always follows the account signed in in the app; a token answered 401 is forgotten, and the widget asks to open MossyDew until the app has a new one. Deleting the user deletes their tokens. — `DeviceToken`, `IssueDeviceTokenHandler`, `RevokeDeviceTokenHandler`, `MainActivity`, `Browser`
- **AP3** `/widget/*` is a stateless firewall that accepts only `Authorization: Bearer <device token>` (401 otherwise); the token opens nothing else: the JSON API stays session-only (A3) and `/integrations/*` takes only the Injust token (I2), which does not open `/widget/*` either. The token's owner is the current user, so the widget sees and changes only their tasks (another user's task answers 404, A3). — `DeviceTokenHandler`, `security.yaml`
- **AP4** `GET /widget/today` answers the user's day (`date`, in their time zone, A4), their theme (`background`, `accent`, `dark`, or `null` until they choose one, A5) and `tasks`: the open tasks of Today, From earlier included (T3), in the ordering rule (M3), then the tasks completed today. Inside each of these two parts, a subtask whose parent is in the same part comes right under it (`nested`, in the order they were added, S2); every other task keeps its place. An open task with an open subtask is `locked`: it cannot be ticked by hand (S3). Each task gives its `id`, `title`, `quadrant` and `done`. The widget's count of tasks left covers every open task it lists, From earlier included. — `ListWidgetTasksHandler`, `WidgetView`, `WidgetTaskView`
- **AP5** Ticking a task in the widget completes it exactly as in the app (`POST /widget/tasks/{id}/complete`, 204): reward once (G1), streak, dew, achievements, the parent completed by its last subtask (S3), the next occurrence of a repeating task (R2), the Injust Release journal (I6). Unticking a task done today reopens it (`POST /widget/tasks/{id}/reopen`, 204, S4). A refused change answers 422 like the JSON API. The widget shows no level-up reveal nor any celebration. A tick that cannot reach MossyDew stays ticked on Android and is sent when the network is back (a server error is retried a few times, then dropped); on the iPad it is undone at the next refresh. — `CompleteWidgetTaskController`, `ReopenWidgetTaskController`, `CompleteTaskHandler`, `ReopenTaskHandler`, `TickWorker` (Android), `ToggleTaskIntent` (iPad)
- **AP6** Tapping a task's box ticks it; tapping the title **Today** or the empty space of the widget opens the app on Today, where tasks are edited. The widget refreshes about every 30 minutes, after each tick and when the app goes to the background (the iPad one also just after midnight), and never shows a list fetched on an earlier day. — `TodayWidget` (Android and iPad)
